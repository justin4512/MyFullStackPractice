# BDD 文件 ─ 賈斯汀 AI 課程商業應用網站

> 行為驅動開發（Behaviour Driven Development）
> 以「使用者看得到的行為」定義驗收條件，語法採 Gherkin（Given / When / Then）。
> 版本：v1.0　撰寫日期：2026-09-09

---

## 0. 角色與名詞定義

| 名詞 | 說明 |
| --- | --- |
| 顧客（Customer） | 一般訪客，可瀏覽課程、加入購物車、送出報名單 |
| 管理員（Admin） | 透過頁面上方按鈕切換的模式，可新增／刪除課程 |
| 課程卡（Course Card） | 桌遊風格卡片，正面為視覺與價格、背面為描述與名額 |
| 選課車（Cart） | 右側常駐面板，可調整數量、顯示小計與總金額 |
| 名額（Seats） | 每堂課開課人數固定 50 人，`status` 欄位反映剩餘名額 |
| API_URL | Google Apps Script Web App 端點，於 `main.js` 最上方統一維護 |

## Feature 1：課程資料載入與防呆

```gherkin
功能: 從 Google 試算表載入課程清單

  背景:
    假設 我開啟「賈斯汀 AI 課程商業應用網站」

  場景: 成功載入課程
    假設 API_URL 已正確設定且後端回傳 { status: "success", data: [...] }
    當  頁面完成初始化
    那麼 畫面應先顯示 8 張骨架載入卡（shimmer 微光動畫）
    而且 資料到達後應以淡入位移動畫依序呈現課程卡
    而且 每張卡片應包含 課程圖片、名稱、分類標記、描述、價格

  場景: 後端連線失敗時的降級模式
    假設 API_URL 為空字串或網路請求失敗
    當  頁面完成初始化
    那麼 應顯示黃色警示列「目前為離線展示資料」
    而且 應改用內建示範課程資料渲染畫面
    而且 不得出現空白頁或 JavaScript 未攔截的錯誤

  場景: 圖片載入失敗自動替換
    假設 某課程的 imageUrl 無法載入
    當  瀏覽器觸發該圖片的 onerror 事件
    那麼 應立即以內聯 SVG 佔位圖（彩墨藍漸層 + 課程圖示）取代
    而且 版面高度不得跳動、不得出現破圖圖示
```

## Feature 2：名額計算與稀缺提示

```gherkin
功能: 依 status 欄位計算剩餘名額

  場景大綱: 名額文字與樣式
    假設 課程開課人數上限為 50 人
    當  該課程剩餘名額為 <剩餘>
    那麼 卡片背面應顯示「<顯示文字>」
    而且 文字樣式應為 <樣式>

    例子:
      | 剩餘 | 顯示文字              | 樣式              |
      | 42   | 還剩 42 個名額        | 一般藍綠色         |
      | 25   | 還剩 25 個名額        | 一般藍綠色         |
      | 24   | 僅剩 24 名，欲購從速  | 紅色粗體 + 脈動動畫 |
      | 3    | 僅剩 3 名，欲購從速   | 紅色粗體 + 脈動動畫 |
      | 0    | 名額已滿              | 灰色，加入按鈕停用  |

  場景: status 欄位為非數字文字
    假設 試算表 status 欄位為「熱銷中 (剩 5 名)」
    當  前端解析該欄位
    那麼 應取出數字 5 作為剩餘名額
    而且 因 5 小於門檻 25，應顯示紅色「僅剩 5 名，欲購從速」

  場景: status 欄位為空
    假設 試算表 status 欄位為空白
    當  前端解析該欄位
    那麼 應以開課上限 50 作為剩餘名額（視為全新課程）
```

## Feature 3：桌遊風格課程卡翻牌

```gherkin
功能: 課程卡翻牌互動

  場景: 桌機滑鼠移入翻牌
    假設 我使用具備 hover 能力的裝置
    當  我把滑鼠移到某張課程卡上
    那麼 卡片應以 Y 軸 3D 翻轉（約 0.7 秒）顯示背面
    而且 背面應顯示 完整描述、剩餘名額、「加入課程」按鈕
    而且 滑鼠移開後應翻回正面

  場景: 觸控裝置點擊翻牌
    假設 我使用不支援 hover 的觸控裝置
    當  我點擊課程卡的空白區域
    那麼 該卡片應翻至背面並保持
    而且 再次點擊應翻回正面

  場景: 尊重系統減少動態偏好
    假設 我的系統設定為 prefers-reduced-motion: reduce
    當  我瀏覽網站
    那麼 背景漂移動畫與翻牌動畫應大幅減弱或停用
    而且 所有資訊仍可完整閱讀
```

## Feature 4：選課車（購物車）

```gherkin
功能: 選課車數量與金額計算

  場景: 加入課程
    假設 課程「AI Agent 智能代理人實作工作坊」售價 8200 且尚有名額
    當  我點擊該卡片背面的「加入課程」
    那麼 右側選課車應新增一列該課程，數量為 1
    而且 選課車標題徽章數字應加 1 並播放彈跳動畫
    而且 總金額應為 NT$ 8,200

  場景: 重複加入同一課程
    假設 選課車中已有「AI Agent 智能代理人實作工作坊」數量 1
    當  我再次點擊該課程的「加入課程」
    那麼 不應新增第二列
    而且 該列數量應變為 2，小計應為 NT$ 16,400

  場景: 以 + 與 - 調整數量
    假設 選課車中某課程數量為 2
    當  我點擊該列的「+」
    那麼 數量應變為 3，小計與總金額應即時更新
    當  我連續點擊「-」直到數量為 0
    那麼 該列應以淡出動畫移除
    而且 若選課車已無項目，應顯示空車插圖與提示文字

  場景: 數量不得超過剩餘名額
    假設 某課程剩餘名額為 2
    當  我嘗試將該課程數量調整為 3
    那麼 數量應維持 2
    而且 應顯示提示「此課程僅剩 2 個名額」
```

## Feature 5：送出報名單

```gherkin
功能: 送出選單至後端

  場景: 未填顧客姓名
    假設 選課車中有課程但姓名欄位為空
    當  我點擊「確認送出選單」
    那麼 姓名欄位應以紅色外框震動提示
    而且 不應發出任何網路請求

  場景: 選課車為空
    假設 選課車沒有任何課程
    當  我點擊「確認送出選單」
    那麼 應顯示提示「請先加入至少一門課程」
    而且 不應發出任何網路請求

  場景: 成功送出
    假設 我已輸入姓名「王小明」且選課車有 2 門課程
    當  我點擊「確認送出選單」
    那麼 應以 fetch POST 送出 action 為 "order" 的 JSON
    而且 送出期間應顯示墨滴載入動畫且按鈕停用
    而且 成功後應彈出美化成功提示框（勾勾描邊動畫 + 訂單編號）
    而且 選課車應清空、姓名欄位應清空
    而且 課程名額應即時扣除並重新渲染卡片

  場景: 送出失敗
    假設 後端回傳 status 為 "error" 或網路中斷
    當  我點擊「確認送出選單」
    那麼 應顯示紅色錯誤提示框並說明原因
    而且 選課車內容必須保留不得清空
```

## Feature 6：管理員模式

```gherkin
功能: 管理員新增與刪除課程

  場景: 切換管理員模式
    假設 我在一般顧客模式
    當  我點擊頁面最上方的「切換為管理員模式」
    那麼 頂部應以向下滑動動畫展開「新增課程表單」
    而且 表單欄位應包含 名稱、分類、描述、價格、圖片網址
    而且 每張課程卡右上角應出現紅色垃圾桶刪除按鈕
    而且 按鈕文字應變為「離開管理員模式」

  場景: 新增課程
    假設 我在管理員模式且已填妥所有必填欄位
    當  我送出新增課程表單
    那麼 應以 fetch POST 送出 action 為 "add" 的 JSON
    而且 期間顯示載入動畫
    而且 成功後應自動重新載入 menu 並將新卡片以高亮動畫呈現
    而且 表單應被清空並收合

  場景: 新增課程欄位驗證
    假設 價格欄位填入負數或非數字
    當  我送出表單
    那麼 應顯示欄位錯誤訊息且不發送請求

  場景: 刪除課程（含二次確認）
    假設 我在管理員模式
    當  我點擊某張課程卡右上角的垃圾桶按鈕
    那麼 應跳出確認對話框顯示該課程名稱
    當  我點擊「確認刪除」
    那麼 應以 fetch POST 送出 action 為 "delete" 與該課程 id
    而且 成功後該卡片應以碎裂淡出動畫移除
    而且 Google 試算表中對應列應被刪除
    而且 若該課程存在於選課車中，也應一併移除

  場景: 取消刪除
    當  我在確認對話框點擊「取消」
    那麼 對話框應關閉且不發送任何請求
```

## Feature 7：退貨與名額回補

```gherkin
功能: 依訂單編號退貨，把名額加回課程

  背景:
    假設 我已開啟管理員模式
    而且 管理員面板下方顯示「訂單退貨」區塊

  場景: 訂單編號下拉選單
    當  我進入管理員模式
    那麼 系統應讀取 orders 工作表並填入訂單編號下拉清單
    而且 每個選項應顯示 顧客姓名與訂單金額
    而且 讀取失敗時仍可手動輸入訂單編號

  場景: 成功退貨
    假設 訂單「ORD-20260909-001」包含課程 AI-101 共 2 堂
    而且 AI-101 目前剩餘名額為 48
    當  我輸入該訂單編號並點擊「辦理退貨並回補名額」
    而且 我在確認對話框點擊「確認退貨」
    那麼 應以 fetch POST 送出 action 為 "return" 的 JSON
    而且 期間應顯示墨滴載入動畫
    而且 成功後 AI-101 的剩餘名額應回補為 50
    而且 應顯示成功提示框並列出回補明細
    而且 該筆訂單在試算表中應被標記為「已退貨」

  場景: 名額回補不得超過開課上限
    假設 某課程剩餘名額為 49 且退貨數量為 3
    當  退貨完成
    那麼 該課程剩餘名額應為 50（夾擠於開課上限）

  場景: 重複退貨
    假設 訂單「ORD-20260909-001」已標記為「已退貨」
    當  我再次對該訂單辦理退貨
    那麼 後端應回傳錯誤「先前已辦理過退貨，不可重複退貨」
    而且 名額不得再次增加

  場景: 未填訂單編號
    當  我未輸入訂單編號就點擊「辦理退貨並回補名額」
    那麼 欄位應以紅色外框震動提示
    而且 不應發出任何網路請求

  場景: 已退貨訂單不得再出現在下拉選單
    假設 orders 工作表中「ORD-20260909-002」的 status 為「已退貨」
    當  我進入管理員模式並展開訂單編號下拉選單
    那麼 清單中不應包含「ORD-20260909-002」
    而且 欄位提示文字應顯示目前可退貨的訂單筆數
```

## Feature 8：翻牌特價（隨機折扣）

```gherkin
功能: 每張課程卡第一次翻牌時抽出專屬折扣

  場景: 卡片正面永遠不揭露折扣
    當  我瀏覽課程牌組
    那麼 卡片正面應只顯示「定價」與「翻牌有驚喜」
    而且 不論該課程是否已抽出折數，正面都不得出現折數印章、折後價或折扣文字

  場景: 第一次翻牌抽出折數
    當  我第一次把滑鼠移到某張課程卡上
    那麼 卡片應播放金色施法特效（光流、靈光、符文魔法陣與火花）
    而且 應隨機抽出一個 75 ~ 99 之間的折數並鎖定
    而且 卡片**背面**應顯示折數徽章與「本次課程可打 NN 折」
    而且 卡片**背面**應顯示「定價刪除線 → 折後新價格」
    而且 加入按鈕金額應更新為折後價

  場景: 重複翻牌沿用同一折數
    假設 課程「AI-101」第一次翻牌抽到 79 折
    當  我再次翻開同一張卡片（不限次數）
    那麼 折數應仍為 79 折
    而且 不應重新抽籤，也不再播放符文魔法陣特效

  場景: 不同課程各自獨立抽籤
    當  我依序翻開 AI-101 與 AI-102
    那麼 兩張卡片的折數應各自獨立產生並分別鎖定

  場景: 重新整理後仍沿用折數
    假設 我已翻開 AI-101 並抽到 79 折
    當  我重新整理頁面
    那麼 AI-101 應仍為 79 折（折數保存於 localStorage）
    而且 瀏覽器停用儲存時應退回「僅本次瀏覽有效」，不得報錯

  場景: 折後價套用至購物車與訂單
    假設 AI-101 定價 3200 且鎖定折數為 79 折
    當  我把它加入選課車
    那麼 選課車該列應顯示 79 折徽章、定價刪除線與折後價 NT$ 2,528
    而且 總金額應以折後價計算
    而且 送出訂單時應一併傳送 discount 欄位，由後端以「試算表定價 × 折數」覆算金額
```

## Feature 9：版面配置

```gherkin
功能: 課程牌組與選課車視覺齊高

  場景: 桌機版面
    假設 我以 1200px 以上的寬度瀏覽
    那麼 標題、搜尋框與分類篩選應橫跨整頁寬度置於上方
    而且 課程卡網格與選課車應從同一條水平線開始（上緣齊高）
    而且 選課車高度應填滿可視範圍，並在捲動時維持固定

  場景: 管理員新增課程可選開課名額
    假設 我在管理員模式的新增課程表單
    那麼 應有「開課名額」下拉選單，預設為 50 人（滿編）
    而且 可選擇 6 ~ 50 人的其他級距
    當  我以 20 人送出新增
    那麼 該課程於試算表的 status 欄位應寫入 20
    而且 成功提示應顯示「開課名額 20 人」
```
