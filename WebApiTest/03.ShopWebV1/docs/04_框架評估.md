# 架構評估 ─ React / Vue / Angular 是否適用本專案

> 需求 8 的回應。結論先講：**本專案目前規模，最佳解是「原生 JS（Vanilla）+ 模組化分區」，
> 若未來要擴充，第二順位建議 Vue 3。**

---

## 1. 本專案的技術特徵

| 特徵 | 內容 | 對框架選擇的影響 |
| --- | --- | --- |
| 部署形式 | 純靜態三檔（HTML/CSS/JS），可直接雙擊開啟或丟 GitHub Pages | 無 build pipeline 需求，框架的打包工具反而是負擔 |
| 後端 | Google Apps Script Web App，單一端點 4 個 action | 資料層極簡，不需要 GraphQL / 複雜快取 |
| 畫面規模 | 單頁、兩個主要區塊（課程網格 + 選課車）+ 一個管理表單 | 元件數 < 10，無路由需求 |
| 狀態複雜度 | courses / cart / adminMode / loading，約 5 個欄位 | 不需要 Redux、Pinia、NgRx |
| 視覺權重 | 極高（桌遊翻牌 3D、背景漂移動畫、墨滴 Loading） | 重點在 CSS 動畫與 GPU 合成，框架幫助有限，甚至因重繪造成動畫中斷 |
| 團隊 | 教學／個人專案，需「可直接複製執行」 | 零依賴 = 零安裝成本，最符合教學情境 |

---

## 2. 三大框架逐一評估

### 2.1 React

| 面向 | 評價 |
| --- | --- |
| 優勢 | 生態系最大、`useState`/`useReducer` 管理購物車非常自然；社群動畫方案（Framer Motion）成熟 |
| 劣勢 | 需 Node + 打包（或用 CDN + Babel 即時編譯，效能差且不適合正式環境）；JSX 讓「三檔分離」的教學需求破功；重繪會重建 DOM，翻牌／背景動畫需額外用 `key` 與 `memo` 保護 |
| 適用時機 | 課程數擴充到需要分頁、搜尋、會員中心、多路由時 |
| **綜合評分** | ★★★☆☆（3 / 5） |

### 2.2 Vue 3

| 面向 | 評價 |
| --- | --- |
| 優勢 | **可直接用 CDN + `createApp()` 漸進式導入，不需要 build**；模板語法接近原生 HTML，最貼近本專案「三檔分離」的結構；`ref/computed` 讓「小計／總金額」寫成一行；`<Transition>` 內建進出場動畫，與購物車增刪動畫天生契合；中文文件完整，教學友善 |
| 劣勢 | 仍多一層 runtime（約 34KB gzip）；本專案 DOM 量小，效益不明顯 |
| 適用時機 | 專案要加入「篩選 + 排序 + 收藏 + 訂單查詢」等多狀態互動時，第一順位 |
| **綜合評分** | ★★★★☆（4 / 5） |

### 2.3 Angular

| 面向 | 評價 |
| --- | --- |
| 優勢 | TypeScript 強型別、DI、RxJS 適合大型企業後台；表單驗證（Reactive Forms）功能最完整 |
| 劣勢 | 必須 CLI 與完整專案結構，學習曲線最陡；bundle 體積最大；為了一個單頁選課站導入等同殺雞用牛刀；與「可直接複製執行的 HTML」需求直接衝突 |
| 適用時機 | 若日後演化為含權限、報表、金流對帳的完整企業後台 |
| **綜合評分** | ★★☆☆☆（2 / 5） |

## 4. 結論與演進路線

**現階段（v1）**：採用原生 JS，但以框架思維組織程式碼 ——
單一 `state` 物件、`render()` 單向資料流、純函式與副作用分離、事件委派。
如此可獲得框架的可維護性，同時保有零依賴與完全的動畫掌控權。

**演進路線建議**

```
v1  Vanilla JS（目前）
      │  課程數 > 50、需要搜尋/排序/分頁
      ▼
v2  Vue 3（CDN 版，仍為三檔分離）── 把 render() 換成模板，state 換成 reactive()
      │  需要會員系統、訂單查詢、多路由
      ▼
v3  Vue 3 + Vite + Pinia + Vue Router（正式打包）
      │  演化為企業內部後台、需權限與報表
      ▼
v4  評估 Angular 或 Next.js（依團隊技術棧決定）
```

**遷移成本已預先降低**：本次 `main.js` 的純函式區（`cartAdd`、`cartTotals`、`buildOrderPayload`…）
完全不依賴 DOM，日後改用任何框架時可 **原封不動搬移**，只需改寫渲染層。
