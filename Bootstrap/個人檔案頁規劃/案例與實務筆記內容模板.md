# 案例與實務筆記內容模板

固定底層順序：**Why（動機）→ How（採用什麼方法、負責什麼）→ What（解決什麼問題、結果如何）**。

本文件為編輯模板，方括號內容需要填寫；空白欄位、編輯提示及尚未驗證的主張不出現在公開網站。

## A. 共用資料欄位

| 欄位 | 填寫內容 |
| --- | --- |
| 名稱 | [專案／文章名稱] |
| 類型 | [案例／實務筆記] |
| 網址代稱 | [簡短、穩定、描述主題的 slug] |
| 作者 | [與個人介紹頁一致的姓名] |
| 時間 | [專案時間；首次發布及實際內容更新日期] |
| 狀態 | [設計／PoC／已完成／已部署／持續維運，依事實選擇] |
| 我的責任 | [主導、獨立實作、團隊協作或其他；列明實際範圍] |
| 參與者 | [需說明的協作者與分工] |
| 技術 | [實際使用；只有規格選型時明確標示] |
| 實際作品網址 | [可公開且能正常開啟的網址；無則省略] |
| 封面 | [截圖或圖片、替代文字、尺寸] |
| 證據 | [畫面、程式、文件、測量紀錄、資料來源] |
| 相關內容 | [同站案例、筆記、作者頁的連結] |

## B. 共用三句摘要

> **動機：**我希望 [使用者／團隊] 能夠 [想促成的改變]。
>
> **方法與責任：**我負責 [實際範圍]，採用 [方法]，並以 [關鍵取捨] 處理需求。
>
> **問題與結果：**針對 [具體問題]，目前 [可觀察的結果／狀態]；證據為 [來源／數據／畫面]，適用限制是 [必要限制]。

公開頁可用自然段落呈現，維持上述順序即可。搜尋摘要依同順序濃縮，不為了填關鍵字改變事實。

## C. 獨立案例正文

### 1. Why｜我為什麼投入這件事

[說明服務誰、希望促成的改變，以及這個動機和工作情境的關係。避免只寫「對技術有熱情」。]

### 2. How｜我如何做、負責哪些部分

- **責任邊界：**[本人責任、團隊責任及合作方式。]
- **採用方法：**[從需求理解、資料處理到實作與維運的必要步驟。]
- **關鍵決策：**[至少一個具體選擇，說明理由、替代方式與取捨。]
- **具體做法：**[適合的流程圖、畫面、簡短程式或架構說明。]

### 3. What｜處理了什麼問題、觀察到什麼結果

[回到具體問題，逐一說明如何被處理，並對應畫面或紀錄。]

| 問題 | 可觀察的結果 | 證據與時間 | 狀態／限制 |
| --- | --- | --- | --- |
| [問題 A] | [結果 A] | [來源 A] | [實測／估算／設計／產品規模] |
| [問題 B] | [結果 B] | [來源 B] | [適用條件或待驗證項目] |

若沒有成效量測，展示功能、流程與驗證方式，不補造節省比例。可在此加入「目前限制與下一步」。

### 補充問答與入口

[僅回答讀者對本案例自然產生的問題；每題先清楚回答，涉及較完整推論時再展開 Why → How → What。]

入口：[開啟作品]、[相關筆記]、[聯絡作者]；只提供真實可用的目的地。

## D. 實務筆記正文

### 1. Why｜為什麼值得研究

[來自哪個實際需求或觀察？希望讓誰做出更好的決策？]

### 2. How｜採用什麼方法、我做了什麼

[研究／操作方法、環境版本、本人參與範圍、比較條件與取捨。引用外部技術資訊時附原始官方文件。]

### 3. What｜能處理哪些問題、結果與限制

[可重現的觀察、操作結果、適用情境與不確定性。連回相關案例，幫讀者理解這項方法如何進入實際工作。]

## E. Flex 作品卡精簡模板

- **標題：**[專案名稱]
- **Why：**[一句動機]
- **How：**[一句方法＋本人責任]
- **What：**[一句具證據的成果或目前狀態]
- **標籤：**[最多數個與專案直接相關的技術／領域]
- **圖片與標題入口：**[外部專案網址；另開分頁時清楚提示]
- **第二入口：**[同站「閱讀案例」網址]

圖片滑入遮罩只負責強調入口，不能是理解故事或找到連結的唯一方式。遮罩內不塞完整文案；手機保留可見入口。

## F. 數字的發布前檢查

每個數字都需要：**定義、單位、時間範圍、所屬專案、來源及性質**。

- 實測：說明量測方法與條件。前後比較使用可比較的工作量與口徑。
- 估算：列公式及假設，不寫成已實際省下的成本或人力。
- 產品規模：如站點數、行程天數，保持規模含義。
- 設計／測試目標：標為規格，不當成實作或營運成果。

已確認的自動化數據示例：

> 每月自動化處理量估計折合 **6,160 人工工時**。公式為 **35 人 × 22 個工作日 × 8 小時**，屬等效人工處理量估算。

## G. 上架前內容檢查

- Why → How → What 順序完整且自然；How 說清楚本人責任。
- What 的問題、結果、數據和來源能彼此對應。
- 三句摘要、正文、圖表、卡片與結構化資料使用一致事實。
- 標題、搜尋摘要、作者、日期、封面與替代文字已填妥。
- 重要文字存在 HTML；連結可直接開啟，沒有空白占位內容。
- 同站案例連結與外部作品連結分開，沒有巢狀連結。
- 只更新實際修訂的日期，不為了製造新鮮度修改日期。
