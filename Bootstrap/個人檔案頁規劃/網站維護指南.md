# 履歷網站維護指南

## 開啟網站

入口是專案根目錄的 `index.html`。可以直接用瀏覽器開啟，也可以在 Bootstrap 目錄啟動本機預覽：

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

瀏覽器開啟 `http://127.0.0.1:8765/`。終端機按 Ctrl+C 停止預覽。

目前共有 9 頁：首頁、作品列表、兩個個人作品案例、三個專業案例、筆記列表及第一篇筆記。所有頁面都是靜態 HTML，不需要安裝前端套件。

## 各檔案負責什麼

| 位置 | 用途 |
| --- | --- |
| `css/myAll.css` 的「JUSTIN CHIU PORTFOLIO」區塊 | 全部新增樣式；限定 `.profile-site`，不影響原練習頁 |
| `js/profile.js` | Slider、手機選單、作品篩選與可選的分析事件 |
| `scripts/build-profile.py` | 共用頁框、首頁、列表與卡片資料，產生靜態頁面 |
| `scripts/profile_content.py` | 六篇完整案例／筆記的文字、摘要、數據及相關連結 |
| `images/profile/` | 頭像、主視覺與作品封面 |
| `downloads/Justin-Chiu-Resume-ZH.docx` | 實際可下載的履歷；由規劃資料夾的原始 DOCX 複製 |
| `tests/` | 瀏覽器互動與匯出保護測試 |

修改 CSS、JS 或同名圖片後直接重新整理即可。修改 Python 中的文字、版型或圖片檔名後執行：

```sh
python3 scripts/build-profile.py
```

頁面有「Generated by scripts/build-profile.py」註記。可以直接編輯 HTML 做練習，但下次產生會覆寫這些 HTML；要保留的變更請同步回 Python 版型或內容資料。

## 加入你的照片與專案截圖

目前主視覺是 AI 製作的立體概念插圖，頭像為 JC 縮寫；兩個作品封面是 SVG 概念圖。它們不冒充本人照片或真實系統截圖。

| 圖片 | 建議比例／尺寸 | 更換位置 |
| --- | --- | --- |
| 個人頭像 | 正方形，建議至少 400×400 | 將照片存為 `images/profile/portrait.jpg`，新增至 `build-profile.py` 的 `ASSETS`，更新頁框 `<img class="pf-avatar">` 的路徑與 alt；保留 `avatar.svg` 供 favicon 使用 |
| 木紋主視覺 | 寬幅約 16:9，建議 1600px 寬以上 | 可直接換同名 `workspace.jpg`；左側文字區需保持安靜、偏暗，主體放右側 |
| 排班系統截圖 | 約 16:10，建議 1200×750 | 在 `PROJECTS` 的 clinic `cover` 與 `profile_content.py` 相應頁的 `cover` 更新檔名，加入 `ASSETS` 清單 |
| 冰島地圖截圖 | 約 16:10，建議 1200×750 | 在 `PROJECTS` 的 iceland `cover` 與相應案例 `cover` 更新檔名，加入 `ASSETS` 清單 |

圖片副檔名應符合真正格式；不要把 JPG 重新命名為 SVG。替換後也更新 `alt`／`cover_alt`。實際專案截圖避免顯示員工帳號、個人資料或登入憑證。

封面與內頁圖片已設定響應式比例。更換後檢查手機截圖是否裁掉重要內容；細節需要完整呈現時，可在案例正文新增圖片並提供說明。

## 新增作品

1. 在 `build-profile.py` 的 `PROJECTS` 加入一筆：名稱、分類、封面、外部網址、站內案例路徑、Why／How／What 短文。
2. 在 `profile_content.py` 的 `PAGES` 加入完整案例。可複製現有資料結構，修改 `path`、`title`、`description`、`summary`、`metrics`、`sections` 與 `related`。
3. `summary` 與 `sections` 維持 **Why 動機 → How 方法與責任 → What 問題與結果**。
4. 封面放入 `images/profile/`，加入 `ASSETS` 清單。新分類需要在作品列表新增篩選按鈕，其 `data-filter` 對應卡片的 `filter` 值。
5. 執行產生指令，檢查外部作品與站內案例都能開啟。

## SEO／GEO 與部署匯出

本機版已包含逐頁 title、description、語意化內容、站內連結與 JSON-LD。主要文案直接存在 HTML，停用 JavaScript 仍能閱讀。

正式網域尚未在環境中設定，因此本機版不宣告候選網域為 canonical。確認 `justin.twtesla.com` 可部署後，可執行：

```sh
python3 scripts/build-profile.py --output dist-profile --site-url https://justin.twtesla.com
```

這會在 `dist-profile` 產生網站頁面、必要 CSS／JS／圖片／履歷，以及逐頁 canonical、OG 網址與圖片、sitemap.xml、robots.txt。可部署此資料夾，避免把整個 Bootstrap 練習目錄一併公開。此指令只匯出檔案，不會註冊網域或部署網站。

匯出器會先檢查目的地；發現無關 HTML、樣式或搜尋設定時會停止，避免先覆寫其他網站的檔案。`.profile-build.json` 記錄本工具產生的檔案；不要手動把其他網站的檔案列入它。

上線後再完成 Google Search Console、Bing Webmaster Tools 的網站驗證與 sitemap 提交。搜尋收錄與 AI 引用需用真實資料觀察，並不因加入標記而保證發生。

分析服務尚未連線。`profile.js` 已提供 `profile:action` 自訂事件；若頁面已有 `window.dataLayer` 陣列，也會推送事件：

- `project_open`：開啟外部作品。
- `case_open`：點擊已標記的案例入口。
- `resume_download_click`：點擊履歷下載，不等同下載完成。
- `contact_click`：點擊聯絡入口，不等同實際收到詢問。

這些事件本身不設定 cookies、不對外傳送資料。要使用分析報表，另接現有的分析服務。

## 已確定的數字口徑

6,160 = 35 人 × 22 個工作日 × 8 小時，是自動化處理量換算的**等效人工工時／月**。維持這個名稱，不改成實測省下工時，也不套用到診所排班案例。

排班的 8 項硬規則、6 項軟目標來自設計文件；冰島的 15 天、66 站是行程規模。後續取得真實使用紀錄後，再補充有日期、定義與來源的成效數據。
