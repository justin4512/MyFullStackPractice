> 整併自：`提示詞網站策略０`、`提示詞網站策略１ (V2 規格)`、`提示詞網站策略２`

## 0. 這份文件怎麼用

- **第 1～5 章是「為什麼」**：定位、差異化、溫度原則。做任何功能取捨時回來看這幾章。
- **第 6～13 章是「做什麼」**：資料模型、功能規格、回饋機制。開發時照這幾章寫。
- **第 14～20 章是「怎麼長大」**：冷啟動、成長、指標、風險、優先級。
- 三份原始文件的分歧之處，本文件已做出**明確決斷**，並標註「**決策**」與理由。往後不再重開這些議題，除非有新的市場訊號。

## 1. 一句話定位

> **「賈斯汀的提示詞實戰庫 —— 每一則都寫清楚在哪個模型、什麼情境、實測效果如何，還有我踩過的雷。」**

三份文件對定位有三種說法，收斂如下：

| 來源 | 主張 | 本文件決策 |
|---|---|---|
| 策略０ | 站長親自實測的實戰庫（每則都有情境與實測紀錄） | ✅ **採用為「內容策略」** |
| 策略１ | AI Prompt Toolbox：最快找到並用起來 | ✅ **採用為「產品體驗策略」** |
| 策略２ | 先做個人私藏庫，站穩再談開放 | ✅ **採用為「第一階段範圍」** |

**決策：三者不衝突，是同一件事的三個面向。**

- 內容上，它是**站長的實戰庫**——每一則都是自己真的拿來解過問題、而且寫得出心得的（這是別人抄不走的護城河）。
- 體驗上，它是**工具箱**，不是文章網站（10 秒內找到 → 填空 → 複製）。
- 範圍上，**第一階段不做會員、不做公開投稿**，但資料結構全部預留。

**要放棄的**：不做「通用提示詞大全」。市面上不缺數量，靠數量必輸。

## 2. 受眾：先選一個，不要兩個都要

| 受眾 | 他要什麼 | 他願意回饋嗎 |
|---|---|---|
| **A. 一般上班族／新手** | 「我這個情境該用哪句」 | 幾乎不會 |
| **B. 進階玩家／同行** | 別人的巧思、可拆解的技巧 | 願意，但門檻高 |

**決策：主打 A，暫不碰 B。**

- A 是搜尋與社群進來的主要人流，負責擴散與 SEO。他們幾乎不會回饋，所以**內容必須由站長自己撐起來**，不能指望 UGC。
- B 維護成本高、對嗆風險高，等站穩再說。

**受眾畫像（A 的細分，用於行銷主題包）**：行銷人／小編、工程師／Vibe Coder、教師、PM、自由工作者、內容創作者。

> **前提要講清楚**：沒有現成社群可以徵稿，**冷啟動與長期維護都是一個人的事**（見第 13 章）。這決定了第一階段的所有取捨——內容要精不要多、回饋機制摩擦要低、投稿等有人流再開。

## 3. 差異化：市面上不缺提示詞，缺的是「可信度」

免費提示詞網站已經一大堆。真正的空缺只有三個：

1. **提示詞會過期** —— 模型一改版，去年很神的咒語今年就普通了。幾乎沒有網站敢標「最後實測日期 / 實測模型版本」。**你標了，就贏一半。**
2. **只有咒語、沒有情境** —— 別人給一段文字，不告訴你什麼時候用、什麼時候**不該**用。
3. **沒有失敗紀錄** —— 「我試過這樣改，結果更糟」這種資訊價值極高，卻沒人寫。

### 3.1 因此：內容單位不是「一則提示詞」，而是「一個案例」

每一則收錄的最小完整體是：

```text
一個案例
├── 做什麼？（description）
├── 什麼情境用 / 什麼情境不要用（scenario）★ 靈魂，不是選填
├── 適用模型 + 實測模型版本 + 最後實測日期 ★ 差異化核心
├── 輸入變數（variables）
├── Prompt 本體（content）
├── 範例輸入 / 範例輸出
├── 作者心得與踩雷（authorNote）★ 溫度來源
├── 使用注意事項（instructions / tips）
├── 品質評分
└── 一鍵複製
```

> **收錄鐵則：湊不齊「情境 + 實測日期 + 一句心得」的，不上架。**
> 寧可 30 則有血有肉，也不要 300 則空殼。

## 4. 底層信念：這是一個有人味的工具

Claude 幫忙寫規格容易寫成一台冷冰冰的檢索機器。這一節是拿來抵抗那件事的。

**四個信念：**

1. **這個站是「有人在維護的」，不是「自動生成的」。**
   每則案例都看得到是誰放上來的、什麼時候實測的、他當時想解決什麼問題。使用者要感覺得到背後有一個活人在替他把關。

2. **使用者來第二次時，站要記得他。**
   不需要登入也能有專屬感。這是第一階段最重要的體驗投資（見第 5 章）。

3. **誠實比完美重要。**
   敢標「這則可能已經失效」「這招我試過，更糟」的網站，比一個看起來每則都五顆星的網站可信十倍。**把不確定講出來，是尊重使用者的時間。**

4. **回饋不是「評分」，是「幫大家看門」。**
   文案上永遠不要寫「請為本則評分」，要寫「這則對你有用嗎？你的回報會幫下一個人少走冤枉路」。同一個按鈕，動機完全不同。

## 5. 溫度設計：怎麼讓人覺得「這是我的站」

**核心手法：不做會員系統，但用 localStorage 做出完整的個人工作區。**

### 5.1 六個「它記得我」的機制（第一階段就要做）

| 機制 | 做法 | 為什麼有溫度 |
|---|---|---|
| **我的最愛** | 點星星存進 localStorage，側欄獨立頁籤 | 不用註冊也有個人化，關掉瀏覽器再回來東西還在 |
| **最近使用** | 記錄最近 10 則開啟／複製過的 | 回訪時第一眼就看到「上次那則」 |
| **我的私人筆記** ★ | 每則詳細頁底部一格 textarea，**只存在你的瀏覽器、永不上傳** | 這是把「別人的工具」變成「我的工具」的關鍵動作 |
| **變數記憶** ★ | 記住上次填過的變數值（如「角色＝資深行銷顧問」），下次自動帶入 | 第二次使用時它已經幫你填好一半，最有「它懂我」的瞬間 |
| **個人化首頁區塊** | 「早安，歡迎回來。你上週最常用這三則」 | 讓首頁像工作台，不像商品目錄 |
| **我的複製紀錄** | 本地統計「你已經用這個站複製了 47 次」 | 使用者對自己的累積產生感情 |

> **隱私承諾要明講**：在「我的筆記」旁邊寫一行小字 ——
> 「這些筆記只存在你的瀏覽器，我看不到，也不會上傳。」
> 這句話同時解決信任問題與溫度問題。

### 5.2 微文案準則

**原則：用「一個人對另一個人說話」的語氣，不要用系統語氣。**

| 情境 | ❌ 系統語氣 | ✅ 我們的語氣 |
|---|---|---|
| 複製成功 | 已複製到剪貼簿 | 已複製！去貼上試試看 🚀（附「開啟 ChatGPT / Claude」按鈕） |
| 搜尋無結果 | 查無資料 | 這個情境我還沒收錄。你可以換個說法找找，或告訴我你想解決什麼 |
| 我的最愛是空的 | 尚無收藏項目 | 這裡還空著。看到順手的就按顆星，之後這裡就是你的私人工具箱 |
| 標記失效 | 提交失效回報 | 這則好像不靈了？回報一下，我會去複驗 |
| 有失效警示 | 狀態：異常 | ⚠️ 最近有幾位回報效果變差了，我還沒來得及複驗，用之前先看一下心得 |
| 連線失敗 | API Error 500 | 我這邊的資料還沒抓到，不是你的問題。先看看這幾則離線範例？ |
| 實測日期過舊 | 資料逾期 | 這則上次實測是 6 個月前的事了，模型可能已經變了 |

### 5.3 署名與現身

- 每則案例掛 **「站長實測」**（自建），或 **原作者暱稱 + 出處連結**（收錄／改編他人作品）。
- Footer 明確標註主理人是誰、在做什麼、可以在哪裡找到你。
- 這個站不只是工具，是「你走在 AI 應用前端」的專業人設展現。別人覺得你的 Prompt 好用，就會信任你的專業，進而轉化成合作、接案或諮詢的機會。

## 6. 使用者核心流程

```text
進入網站
   ↓
（回訪者：直接看到「最近使用 / 我的最愛」）
   ↓
搜尋 / 選分類 chips
   ↓
看到卡片（含 ⭐評分、🔥使用數、🕐最後實測日期）
   ↓
展開 → 看情境、看心得、看範例輸出
   ↓
填 {{變數}}（上次填過的自動帶入）
   ↓
即時預覽完整 Prompt
   ↓
一鍵複製 → Toast + 「去 ChatGPT 貼上」按鈕
   ↓
（回來）👍 / 標籤回饋 / 寫私人筆記
```

**體驗目標：10 秒內完成「找到 → 修改 → 複製」。**

## 10. 「非做不可」的核心功能

這幾點是提示詞站跟一般資料查詢站最不一樣的地方：

1. **一鍵複製 + Toast** —— 全站最高頻動作。按鈕要大、要在**卡片正面**就看得到。複製後 `useCount +1`。
2. **變數填空器** ★ —— 最有價值的功能，別省。
   - 自動解析 `{{變數}}` 產生表單
   - **記住上次填過的值**（localStorage）
   - **一鍵清除／恢復預設**按鈕（不然使用者要狂按倒退鍵）
   - 即時預覽完整 Prompt
3. **全文搜尋 + 標籤雙軸過濾** —— 搜尋 `title / description / content / category / subcategory / tags / scenario`，配上分類 chips，即時過濾不重打 API。
4. **換行與格式保真** —— `white-space: pre-wrap`；存 Sheets 走 JSON，不走 CSV，換行才不會被吃掉。
5. **版本／修改紀錄** —— 提示詞是「調」出來的，看得到 v1→v2 改了什麼很重要。詳細頁提供「查看版本差異」。
6. **單則分享連結** —— `prompt.html?id=P001` 自動展開並捲動定位，且要有 **Open Graph tags**（見 15.2）。
7. **我的最愛 / 最近使用 / 我的私人筆記**（localStorage，見第 5 章）。
8. **匯入／匯出 JSON** —— 資料不被 Google Sheets 鎖死，備份、搬家、整包分享都方便。
9. **離線 Demo Mode** —— `const DEMO_MODE = !API_URL;` 內建 15～20 則示範資料。
10. **深色模式 + 鍵盤快捷** —— `/` 聚焦搜尋、`Esc` 關閉 Modal、`Ctrl/Cmd+Enter` 複製、`F` 收藏。這類受眾很吃這套。
11. **邊界狀態設計** —— GAS 逾時、API 網址填錯、離線模式被觸發時，都要有直覺的狀態提示（見 5.2 微文案），不要讓人以為網站壞了。

## 11. 回饋階梯

殘酷現實：**90% 的人只複製、不留言。** 所以不能只放一個留言框然後期待有人寫。要設計成一階一階、摩擦由低到高：

| 階 | 動作 | 摩擦 | 你會拿到什麼 |
|---|---|---|---|
| **0** | 複製（自動記錄） | 零 | 熱門排行的真實訊號 |
| **1** | 「這則有幫助嗎？👍 / 👎」 | 一次點擊 | 品質訊號（比五星好用太多） |
| **2** | 快速標籤：`效果很好`／`需要微調`／`模型不同差很多`／**`已失效`** | 一次點擊 | 結構化資料，可自動排序、自動掛警示 |
| **3** | 一句話心得（限 100 字，不登入，只填暱稱） | 低 | 真人語氣的社會證明 |
| **4** | 投稿改編版（Fork）：基於這則改一版並說明改了什麼 | 高 | 最有價值的內容，自動長出「演化樹」 |

### 三個設計重點

1. **第 2 階的「已失效」是全站最重要的按鈕。** 累積到門檻自動在卡片掛上黃色警示「近期回報效果下降」，並通知你去複驗。**這讓網站會自我維護，而不是越久越爛。**
2. **Fork 是心得的最高形式。** 一則提示詞底下掛著三個使用者改編版，比十則新提示詞更有說服力，也讓投稿者有作品感。
3. **心得要能反向排序提示詞。** 熱門排行不要只看複製數（複製了不代表有用）。

## 12. 評分與排行榜

### 12.1 排行權重（不要只用複製數）

```text
熱度分數 = 👍率 × 近期實測權重 × log(複製數)

近期實測權重：
  testedDate < 3 個月   → 1.0
  3～6 個月            → 0.8
  > 6 個月             → 0.5
  staleFlag = true     → 0.2（且卡片掛警示）
```

### 12.2 多維評分（不要只有單一 rating）

```text
Prompt Score
品質       ★★★★★
穩定度     ★★★★☆
易用性     ★★★★★
模型相容   ★★★★☆
        → 92 / 100
```

### 12.3 多種排行榜（避免只有一個「熱門」）

🔥 本週熱門 ／ 📈 成長最快 ／ ⭐ 最高評分 ／ 🆕 最新加入 ／ 👑 長期熱門 ／ ✅ 最近複驗

## 13. 冷啟動：先當雜誌，再當論壇

**前提：沒有班級可以徵稿，內容從頭到尾靠自己補。** 所以節奏要設計成「一個人可持續」，而不是「等別人來投稿」。

| 階段 | 做什麼 | 開放到第幾階回饋 |
|---|---|---|
| **第 0 週** | **你自己精選 30～50 則**，每則寫滿情境＋實測＋心得。品質基準由你親自立，日後投稿的人會照抄這個格式 | — |
| **第 1 階段** | 只開放 0～2 階（點擊型）。**不開留言、不開投稿**。每週固定補 3～5 則，並複驗最舊的 2 則 | 0–2 |
| **第 2 階段** | 有穩定回訪後才開一句話心得。同時用「主題包」（見 14.4）到各社群換一波流量與真實回饋 | 0–3 |
| **第 3 階段** | 投稿開放，走「審核後上架」（`status: draft → published`），你就是主編 | 0–4 |

> **空城效應對策**：初期先用點擊型回饋撐場，數字看起來就有活力，不會出現「沒人留言 → 更沒人想留言」的死循環。

> **產能對策**：把「每週補 3～5 則 + 複驗 2 則」直接排進行事曆。一個人做站，殺死它的通常不是沒流量，是斷更。

## 14. 成長飛輪與行銷

### 14.1 網站對你的真正價值不是流量

是 **你個人的公開作品集與信任憑證**。

```text
你持續實測並寫下心得 → 網站內容變厚
   ↑                              ↓
專業信任累積 ← 路人搜尋進站看到真實案例 ←┘
```

每則案例掛「站長實測 + 實測日期」。累積一兩年，這就是一份「我真的長期在用 AI 解決問題」的公開紀錄，比任何自我介紹都有說服力。

### 14.2 產品即行銷（PLG）

**輕量出處標記**：使用者透過變數填空器組合完整 Prompt 並複製時，在最尾端（或程式碼類的註解區）自動帶入一行極小的字：

```text
# 整理自 PromptBase｜justin.example.com
```

當使用者把產出截圖分享到社群（Threads / FB / Telegram / Discord），別人就會循著出處找過來。

> ⚠️ **溫度守則**：這行字必須**可以一鍵關掉**，而且預設不擋路。夾帶得太用力，工具就從「我的」變成「他的廣告」，反而傷害第 5 章想建立的一切。

### 14.3 分享連結的 Open Graph

每則的 `?id=P001` 分享到 Line / FB / X / Discord 時，動態抓取該則的**標題**與**情境描述**當預覽卡文字。你就可以在社群或電子報直接發「今天推薦一個專門寫爆款文案的 Claude Prompt」，點進去直接展開，點擊率會極高。

### 14.4 用「主題包」切入不同社群

不要跟所有人說「這是一個 AI 提示詞網站」，太模糊。用情境包（Bundle）行銷：

- **切角 A（行銷人／小編）**：「3 分鐘產出一週社群貼文：20 個高轉換率行銷 Prompt」
- **切角 B（工程師／Vibe Coder）**：「Vibe Coding 必備：讓 AI 幫你抓 Bug 與想架構的私藏 Prompt 庫」
- **切角 C（教師）**：「備課提速：出題、改作業、寫評語的 15 則實測 Prompt」

哪個社群反應最熱烈，就是未來要不要升級成公開共享站的重要市場訊號。

## 16. 指標：別看 PV

| 指標 | 看什麼 |
|---|---|
| **複製率**（複製數 / 瀏覽數） | 內容有沒有用 |
| **👍率** | 品質 |
| **回訪率** | 是不是「工具」而不是「一次性讀物」 |
| **每週新增／複驗則數** | 你自己的產能（斷更是最大風險） |
| **失效回報處理時間** | 內容新鮮度 |
| **變數填空完成率** | 填空器好不好用 |

### 核心 KPI：Prompt → 使用成功率

```text
搜尋 → 查看 → 填變數 → 複製 → 收藏 → 再次使用
```

**「再次使用」是最終指標。** 這比「收錄了幾則」更能判斷網站是否真的有價值。

## 17. 風險與對策

| 風險 | 對策 |
|---|---|
| **內容腐化（最大風險）** | 失效回報 + 每則標最後實測日期，超過 6 個月自動標「待複驗」 |
| 空城效應 | 先用點擊型回饋撐場，數字看起來有活力 |
| 洗版／灌水 | 投稿審核制；回饋節流 |
| 版權 | 必填 `source`，以「改編＋心得」呈現 |
| **變成冷冰冰的資料庫** | 每則必填 `authorNote`；微文案準則（5.2）納入 Code Review 檢查項 |
| **斷更（一人維運的最大風險）** | 每週固定補 3～5 則、複驗 2 則，排進行事曆（見第 13 章） |
| 日後開放投稿的品質參差 | 審核後上架；你是主編，退件也要給修改建議 |
